# Деплой Nuxt на VPS

Настроен для `sasha761/branded-nuxt` → `173.242.54.153`. WordPress, его база, медиафайлы и серверные секреты этим workflow не переносятся.

## Обычная публикация

1. Закоммитьте изменения Nuxt и отправьте их в `master`.
2. Дождитесь зелёного **CI** в GitHub → Actions.
3. Откройте **Deploy → Run workflow → master → Run workflow**.
4. Дождитесь зелёного Deploy. Шаг **Verify public release** проверяет SHA опубликованной сборки на https://branded.com.ua/deploy-meta.json.

Автодеплой при push выключен: `DEPLOY_ON_PUSH=false`. Для его включения измените эту переменную на `true`; публикация произойдёт после успешного CI. Ручной запуск принимает только master и самостоятельно выполняет typecheck, unit-тесты и сборку.

## Настройки GitHub Actions

Settings → Secrets and variables → Actions, уровень репозитория:

| Имя | Тип | Значение |
|---|---|---|
| DEPLOY_HOST | Variable | 173.242.54.153 |
| DEPLOY_USER | Variable | deploy |
| DEPLOY_PORT | Variable | 22 |
| DEPLOY_ON_PUSH | Variable | false |
| DEPLOY_SSH_KEY | Secret | отдельный ключ только этого репозитория |
| DEPLOY_KNOWN_HOSTS | Secret | ключ VPS, сверенный через авторизованную панель |

Нельзя заменять известный ключ сервера непроверенным результатом ssh-keyscan при ошибке проверки. Сначала подтвердите новый отпечаток через панель VPS. Приватный SSH-ключ в репозиторий не добавляется.

## Что выполняется

Linux runner использует Node 26.13.0, как на VPS. После проверок он передаёт `.output` в `/srv/branded/incoming/github/<sha>-<run>-<attempt>`. Пользователь deploy имеет отдельный SSH-ключ с `restrict`, запись только в свой каталог загрузки и sudo только на `/usr/local/sbin/branded-deploy`.

Скрипт проверяет артефакт и доступность WordPress API, копирует файлы с правами branded, переключает `current`, перезагружает два процесса PM2 и проверяет сайт с идентификатором сборки. При ошибке активации возвращает предыдущий релиз. Секрет сброса кеша остаётся в `/etc/branded/nuxt.env.json` на VPS; GitHub его не получает. Старые чанки сохраняются в отдельном каталоге для открытых вкладок. Временная загрузка удаляется после выполнения.

Полные резервные копии этим workflow не создаются. Сохраняются каталоги релизов для быстрого отката; они занимают место и требуют последующей контролируемой очистки.

## Проверка и откат через SSH

```sh
sudo /usr/local/sbin/branded-deploy --status
sudo /usr/local/sbin/branded-deploy --rollback
```

Откат переключает Nuxt на `previous`, проверяет HTTP и сбрасывает кеш. Повторный откат возвращает релиз, который был активен до первого отката. База данных и WordPress не откатываются.

Исходник скрипта: [deploy.py](../docs/vps-setup-2026-11-03/deploy.py). Изменение этого файла в Git не устанавливает привилегированный скрипт автоматически: его обновляет администратор VPS.
