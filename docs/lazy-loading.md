# Настройка lazy-load

Используется [VueUse `useIntersectionObserver`](https://vueuse.org/core/useIntersectionObserver/), прямая зависимость `@vueuse/core`. Она управляет наблюдением за viewport и очисткой наблюдателей при размонтировании Vue-компонентов. Нужная функция импортируется отдельно; Nuxt-модуль подключать не требуется.

## Общее расстояние загрузки

Файл: `app/app.config.ts`.

```ts
imageLoading: {
  viewportOffset: 200,
  carouselNeighbors: 1,
}
```

- `viewportOffset` — запас по высоте от границ видимой области, в пикселях. `200` разрешает загрузку за 200 px до экрана; `0` — только при пересечении с viewport; `500` даёт больше времени на скачивание, но начинает загрузку раньше.
- `carouselNeighbors` — количество соседних карточек по обе стороны видимых. Учитывается после приближения самой карусели к экрану.

После изменения настройки нужна новая сборка и публикация. В коде значение переводится в `rootMargin: '200px 0px'`, то есть запас добавляется сверху и снизу.

## Как это работает

Для отложенных картинок в первоначальном HTML отсутствуют `src` и `srcset`; URL находятся в `data-src` / `data-srcset`. Поэтому собственный большой порог браузерного `loading="lazy"` не может запустить их скачивание раньше заданного расстояния. VueUse сообщает о приближении элемента, после чего Vue назначает настоящие URL. Уже загруженные изображения сохраняются при обратной прокрутке.

`UiCImage` применяется к небольшим баннерам, аксессуарам, статическим изображениям распродажи, блокам Branded и подписки на главной. Декоративный фон LBrand также переведён на этот компонент. Карточки `CProduct` используют ту же настройку расстояния, если загрузкой не управляет карусель или явный eager.

В товарных каруселях больше нет правила «загрузить первые четыре карточки при SSR». Пока блок далеко, все карточки остаются без настоящих URL изображений. При приближении загружаются видимые и соседние карточки; autoplay по-прежнему включается только в самой видимой области.

Главный баннер, LCP-фон и явно eager-карточки каталога загружаются сразу. Следующие слайды главного баннера подключаются при переключении. У изображений внутри HTML WordPress и отдельных всплывающих окон сохраняется нативный lazy-load.

## Файлы реализации

- `app/app.config.ts` — значения настроек.
- `app/composables/useImageViewport.ts` — одноразовая готовность изображения через VueUse.
- `app/components/ui/CImage.vue` — компонент изображения с отложенным src/srcset.
- `app/components/ui/CProduct.vue` — обычные карточки и внешнее управление из каруселей.
- `app/composables/useVisibleCarousel.ts` — отдельные границы для предзагрузки изображений и autoplay.

Размеры контейнеров резервируются до назначения src. В частности, фото распродажи размещаются внутри picture с известным соотношением сторон, чтобы нижние блоки не сдвигались при скачивании.

Адрес LCP-фона сохраняется через `useState`, чтобы SSR и клиент использовали одинаковый URL даже при преобразовании импортов Vite в абсолютные адреса.

## Проверка

После `npm run build`:

```powershell
$env:E2E_WP_URL='https://branded.com.ua'
npm.cmd exec playwright test test/e2e/performance.spec.ts test/e2e/home-performance.spec.ts test/e2e/viewport-loading.spec.ts -- --workers=1
```

Эти сценарии выполняют только чтение. Проверяются сетевые запросы ниже первого экрана, граница 200 px, загрузка баннеров при переключении, остановка autoplay вне экрана, геометрия при задержке изображений и отсутствие ошибок гидратации. Ширины экрана — 390 и 1440 px.
